## Open findings

1. **Iceberg PR #18749: `spark.read.table("t@v<id>")` fails with the SQL extensions on Spark 4.3.0.** Not a Spark bug. Spark 4.3 added `ParserInterface.parseTemporalTableIdentifier` (SPARK-57421) with a default that calls `parseMultipartIdentifier`. Spark's `AbstractSqlParser` overrides it. `IcebergSparkSqlExtensionsParser` (v4.3 module, commit b1eab64) does not override it, so the `@` suffix gives `PARSE_SYNTAX_ERROR`. SQL `FROM t@v<id>` works because `parsePlan` delegates to Spark. Repro: `code/ch45/extensions.py` (row "spark.read.table('t@v<id>')"). Fix: delegate `parseTemporalTableIdentifier` to the wrapped parser. Worth a review comment on #18749. Possible Spark-side doc gap: the default implementation silently drops the suffix support for any parser extension that wraps Spark's parser (Delta's parser likely has the same gap; not checked).
2. **`remove_orphan_files` message** is long and was cut at 300 characters in the saved output; the chapter quotes only its first two sentences. Not a bug.
3. Not checked: the S3 path (`iceberg-aws-bundle`), the draft post covers it on 4.1.4. Concurrent writers and commit conflicts are not shown (Chapter 44 territory).
