## Open findings

1. **Airflow provider 6.3.4: `track_driver_via_k8s_api` works only in a namespace named `spark`.** `SparkSubmitHook._process_spark_submit_log` matches `submission ID spark:(.+?-driver)`. Spark logs `submission ID <namespace>:<pod>` (`KubernetesClientApplication.scala`, `Client.submissionId(conf.namespace, driverPodName)`). With any other namespace, `_kubernetes_driver_pod` stays `None`, the task raises `RuntimeError: spark-submit did not capture a K8s driver pod name`, and the driver pod keeps running (orphaned; a retry submits a duplicate). The unit test `test_process_spark_submit_log_k8s_submission_id_format` uses namespace `spark`, which hides it. Minimal repro (no cluster needed):
   ```python
   hook = SparkSubmitHook(conn_id="spark_k8s_cluster")   # any k8s:// cluster-mode connection
   hook._process_spark_submit_log(["INFO Client: Deployed Spark application x with application ID "
       "spark-1 and submission ID spark-jobs:x-c8e2e29e73db9c93-driver into Kubernetes"])
   assert hook._kubernetes_driver_pod is None   # expected "x-c8e2e29e73db9c93-driver"
   ```
   Full run: `CH48_SUBMIT_CONN=spark_k8s_jobs ch63/af.sh dags test ch63_taxi_k8s` (output `code/ch63/output/dag_k8s_namespace_bug.txt`). Lisa contributes to this provider; a candidate fix is `submission ID [^:\s]+:(\S+-driver)`. Not filed.
2. **Airflow provider 6.3.4: `SparkConnectHook` error message not formatted.** `raise ValueError("Path {url.path} is not supported ...")` lacks the `f` prefix. Lisa already has a branch for this (`spark-connect-hook-path-error-message` in `~/repos/airflow-spark-provider`); not in 6.3.4.
3. **Spark 4.3.0: third-party shuffle managers must now extend the `private[spark]` trait `BlockingShuffleManager` (SPARK-58185), and the core migration guide does not say so.** Celeborn 0.7.0 fails at `SparkEnv.initializeShuffleManager` with `IllegalArgumentException: spark.shuffle.manager must be a BlockingShuffleManager`. Doc gap candidate (migration guide entry for plugin authors). Repro: `ch63/celeborn_job.sh celeborn 4.3.0` (output `celeborn_celeborn_430.txt`). Other plugins (Uniffle, Gluten's shuffle) likely affected; not checked.
4. **Spark 4.3.0, minor: after the SparkContext init failure in finding 3, cleanup logs `NullPointerException: Cannot invoke "org.apache.spark.Heartbeater.doReportHeartbeat()" because ... _heartbeater() is null`** from `Utils.tryLogNonFatalError`. Noise on an already-failed start; not a correctness bug. Not checked on master.
5. **cncf-kubernetes 10.25.0: `SparkKubernetesOperator` creates the custom object before it validates the spec**, so a non-Kubeflow `SparkApplication` (the Apache operator's) starts on the cluster while the task fails with `KeyError: 'driver'` (`dag_wrong_operator.txt`). Possibly worth a guard on `apiVersion` (reject anything but `sparkoperator.k8s.io`). Not a Spark bug.
6. **`kubernetes==36.0.3`: `CoreV1Api.read_namespaced_pod_log` returns `str(bytes)` (text that starts with `b'`)** in this environment, so line filters miss everything. The DAG uses `KubernetesHook.get_pod_logs(...).data.decode()`. Not investigated further.
